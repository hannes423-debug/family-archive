Why living people are not shown

This site is public. The people in it are not all dead, and the ones who are alive did not ask to be on the internet.

So the published tree shows living people by surname only. Their given names, dates of birth, birth places, occupations and notes are stripped out before anything is committed. You can see that they exist and where they sit in the family — that is what makes the tree legible — but nothing that identifies them individually is here.

How "living" is decided

  • A recorded death or burial means the person is treated as deceased and is shown in full.
  • Otherwise, someone born more than 100 years ago is presumed deceased — the same threshold Ancestry and MyHeritage use.
  • Everyone else is treated as living, including anyone with no dates recorded at all. When the data is ambiguous the rule errs toward withholding, because the other kind of mistake publishes a real person's details.

What that means in practice

The redaction happens in the generator, not in the browser. The published tree.json never contains the withheld values, so they cannot be recovered by reading the page source, disabling JavaScript, or fetching the data file directly. There is no hidden field and no client-side filter to switch off.

A deploy is also gated on an independent check that re-reads the generated file and fails the build if a living person still carries a name, a date, a place or a note. Nothing reaches this site if that check does not pass.

Editing

This tree can be edited in the browser by whoever maintains it, and saved straight back to GitHub. Editing changes nothing about what is published: the same rule applies to anything typed into the editor, and it is enforced in three independent places — the form does not offer those fields for a living person, every write strips them again, and a final check re-reads the finished file and refuses to publish if anything slipped through.

You cannot mark a living person as deceased to unlock their details. An ancestor whose dates are unknown can be recorded as deceased, date unknown — that is a real genealogical statement — but for anyone born in the last 25 years that is not accepted, and an actual death date is required.

Only someone holding a GitHub token with write access to the repository can save anything. Opening the editor changes nothing on its own.

Photographs

The same rule governs images. A photograph can only be attached to someone the archive treats as deceased; the editor does not offer the list for a living person, and the check that gates publishing rejects any file attached to one. Every photograph published here shows a person who has died, a gravestone, or a historical document.

Filenames are rewritten before publication. That is not tidiness — a path is published just as surely as the file it points at, and the original folders were named after a living relative, so the directory listing alone would have given away what the tree withholds.

The source data

The original GEDCOM this tree was imported from is not in the public repository and never has been. It lives offline.

There is deliberately no private store behind this site: no second database holding the withheld details. For living people those details are not kept anywhere in this system at all — so there is nothing here to leak, and nothing to accidentally publish later.

If you are in this tree

If you would rather not appear at all, even as a surname, that is a reasonable thing to ask and it will be honoured. Ask the family member who maintains this archive and the record will be removed from the published view.
